# Налаштування Telegram і Resend для сповіщень

Ця інструкція для клієнта: як підготувати бота Telegram і домен у Resend, щоб сайт надсилав сповіщення персоналу про нові заявки, звернення та відгуки.

## Що передати нам

Надішліть **лише назви змінних і значення** через захищений канал (менеджер паролів, зашифрований файл, захищений тікет). **Не пишіть токени й ключі у звичайний чат відкритим текстом.**

Потрібні значення:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `RESEND_API_KEY`
- `EMAIL_FROM` (адреса з підтвердженого в Resend домену)
- `NOTIFY_EMAIL_TO` (один або кілька email персоналу через кому)

## Telegram-бот

1. Відкрийте Telegram і знайдіть `@BotFather`.
2. Надішліть `/newbot`, задайте імʼя та username бота.
3. BotFather поверне токен вигляду `123456:ABC...` — це `TELEGRAM_BOT_TOKEN`.
4. Додайте бота в групу (або канал), куди мають падати сповіщення. Для групи надайте боту право писати повідомлення.
5. Дізнайтеся `chat_id`:
   - напишіть боту або згадайте його в групі;
   - відкрийте в браузері  
     `https://api.telegram.org/bot<TOKEN>/getUpdates`  
     (підставте свій токен замість `<TOKEN>`);
   - у відповіді знайдіть `"chat":{"id": ...}` — це `TELEGRAM_CHAT_ID`;
   - для груп id зазвичай **відʼємний** (наприклад `-1001234567890`);
   - альтернатива для особистого чату: бот `@userinfobot` (або подібний) покаже ваш id.
6. Можна вказати кілька чатів через кому: `-100111,-100222`.

## Resend (email)

1. Зареєструйтесь на [resend.com](https://resend.com).
2. Додайте свій домен (Domains → Add Domain).
3. У панелі Resend зʼявляться DNS-записи: **SPF**, **DKIM**, **DMARC** (і інші, якщо Resend їх покаже). Додайте їх у DNS хостингу домену точно як у панелі.
4. Дочекайтеся статусу **Verified** для домену.
5. Створіть API key з доступом **Sending** — це `RESEND_API_KEY`.
6. `EMAIL_FROM` має бути з підтвердженого домену, наприклад `Оператор <noreply@ваш-домен.com>`.
7. `NOTIFY_EMAIL_TO` — куди слати сповіщення персоналу (форми на сайті **не** збирають email клієнта, підтвердження клієнту не надсилається).

## Як ми перевіряємо

Після додавання змінних у середовище сервера:

```bash
python manage.py test_notifications
```

Очікуваний результат у консолі: рядки `Telegram: OK` та/або `Email: OK`.  
Можна перевірити окремо: `--telegram`, `--email`, або `--to someone@example.com` для тестового одержувача email.

Команда **ніколи** не друкує значення токена чи API-ключа.
